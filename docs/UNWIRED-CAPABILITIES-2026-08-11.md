# Unwired capability audit — 2026-08-11

**Question asked:** "how much dead code is in `src/`, and should we delete it?"
**Answer:** almost none is dead. What the scan actually found is **finished
back-end work with no UI attached** — features we already paid for and are not
shipping.

## How this was measured

`knip` crashes on this machine (`RangeError: Array buffer allocation failed`
inside `oxc-parser` — it allocates the whole project in one ArrayBuffer, and
16 GB is not enough; `--max-old-space-size` does not help because that memory is
external to V8). So the scan was a ~70-line Python walk of `src/`: collect every
exported name, then flag any name that appears in **no other file**.

```
files scanned ............ 463
exported names ........... 885
zero external reference ... 135
```

Blind spot checked and closed: `vitest.config.ts` includes
`functions/src/**/*.test.ts`, but **`functions/` does not exist** — that include
is dead config. `supabase/` contains no references to any flagged name, so the
135 really are unreferenced repo-wide.

## Why 135 is not 135 deletions

| Class | Count (approx.) | Verdict |
|---|---|---|
| Generated file (`src/lib/supabase/database.types.ts`) | 5 | **Untouchable.** `Enums`, `Constants`, `TablesInsert`, `TablesUpdate`, `CompositeTypes` are regenerated by the Supabase CLI. Deleting them means the next `generate types` puts them back. |
| Type aliases | ~95 | **Keep.** TypeScript types are erased at build time — they cost literally zero bytes in the bundle. Deleting them is churn with a non-zero chance of breaking a build. |
| Over-exported internal helpers | ~30 | **Keep.** These are *called*, just not across a file boundary. `decideStripeEventClaim` (`src/domain/payments/rules.ts:279`) is invoked at `rules.ts:302` by another function in the same file. The scan cannot see same-file calls. Removing the `export` keyword would be correct-but-pointless. |
| Genuinely dead runtime function | 1 | **Delete.** See below. |

**Conclusion: no mass deletion.** A 135-symbol sweep is a large blast radius
for zero user-visible benefit and zero bundle-size benefit.

## The one real deletion

`verifySkillsetCertificate` in `src/lib/data/certificates.ts` — superseded by its
own in-file comment:

```
// In-app verification path (authenticated or anon session). Public embedders
// use verifySkillsetCertificatePublic (Route Handler with CORS) instead.
```

The only consumer (`src/components/certificates/certificate-verification-panel.tsx:9,35`)
uses the `Public` variant. Removed in the same commit as this document.

## What the scan actually surfaced: built, not wired

Each row below is back-end work that exists, compiles, and has no UI reaching it.
Priority is product value, not code size.

### 1. Language switcher (en / es) — REAL GAP

- `src/lib/i18n/config.ts` exports `LOCALES`, `LOCALE_LABELS`, `LOCALE_SHORT_LABELS` — **nobody imports them.**
- `DEFAULT_LOCALE` and `LOCALE_COOKIE` *are* consumed, so the cookie plumbing and `<html lang>` work.
- `src/components/i18n/i18n-provider.tsx` exists.
- Design note in the file: no `[locale]` route segments on purpose — locale lives in a cookie so every route keeps working.

The labels exist for exactly one reason: to render a picker. **The picker was never built.** Spanish is one component away from shipping.

### 2. Gamification progress bar — REAL GAP

- `src/domain/gamification.ts:53` exports `levelProgress` — no caller.
- `levelForPoints` *is* consumed, so members already have a level number.
- `LEVEL_THRESHOLDS` (Skool's published ladder: 0, 5, 20, 65, 155, 515, 2015, 8015, 33015) is unreferenced outside the file.

Members see a level; they cannot see how close the next one is. The math is written.

⚠️ Before touching this file, read its SOURCE OF TRUTH note: the like-award job
runs **outside this repo** and carries its own copy of the thresholds.

### 3. Homepage content blocks — REAL GAP

- `src/data/site.ts:46` — `featuredTracks` assigned, never rendered.
- `src/data/site.ts:52` — `marketplaceHighlights` assigned, never rendered.

Two homepage sections defined and dropped on the floor.

### 4. Catalog fetchers — NEEDS A PRODUCT CALL

`src/lib/data/catalog.ts` exports 8 things. Consumers import 5. Unconsumed:

| Function | What it would power |
|---|---|
| `getCourses` | a full catalog / browse-all page |
| `getCommunitySpaces` | a communities directory |
| `getLiveEvents` | a live-events calendar |

These are three unbuilt pages, not dead code. Decide whether we want the pages.

### 5. Analytics taxonomy bypassed — FLAG, NEEDS VERIFICATION

`src/lib/posthog/events.ts` defines `EVENTS` (15 event-name constants),
`EventName`, and 13 `*Props` types. Its own docstring says:

> Import the constants instead of using magic strings so we can rename an event in one place if needed.

Five files import `track` from that module; **none import `EVENTS`.** So event
names are very likely being passed as raw strings, defeating the point of the file.

**Not asserted as fact** — a follow-up grep for the actual call shape returned
nothing, which is inconsistent with 5 importers and needs a human look before
anyone "fixes" it.

### 6. Feature-flag and permission registries — CANDIDATES

- `src/lib/feature-flags`: 3 consumers, all importing only `isPublicFeatureEnabled`. `featureFlagDefinitions`, `allFeatureFlagDefinitions`, `getPublicFeatureFlagOverrides` + types unconsumed.
- `src/lib/permissions`: 13 consumers, importing only `Role`, `Permission`, `PermissionSubject`, `hasPermission`, `hasAnyPermission`. `permissionDefinitions`, `allPermissionDefinitions`, `rolePermissionMatrix` + types unconsumed.

Both registries look built for an **admin screen** ("here are all flags / all
roles and what they can do") that does not exist. Keep until that call is made.

## Disproved

**Installments are NOT a gap.** Both type aliases in `src/domain/installments.ts`
are unreferenced *by name*, which looked like an unwired module. It is not — 12
files reference installments, including `api/payments/checkout/route.ts`,
`course-builder-studio.tsx`, `sales-page-editor.tsx`, and `payments/server/stripe.ts`.
Hotmart-style installment display plus Stripe card installments are live.

The lesson: a flagged *symbol* never proves an unwired *module*. Check the module.
